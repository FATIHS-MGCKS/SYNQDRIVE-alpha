# C5.1 — Gated local repair architecture (design only)

**Status:** Research design gate — no implementation in this workstream.  
**Production kinematics pin:** `579ee8b2fed06593d7d2aa57cffb6036dbf53a24`  
**Supersedes for fleet authority:** C5 PTQ V0 (#2142, `NOT_PROVEN`) — must not ship as-is.

## Problem statement

C4 (`computeC4AdaptiveL3`) is the production-parity speed authority. Root-cause work (#2140) and DIMO probe (#2141) show **isolated timing/label mis-assignment** on otherwise coherent geometry (TES16 `03:50:20–23`), while C5 V0 demonstrated that **global PTQ re-estimation** fixes some tails but **sacrifices coverage** (115 C4-numeric seconds lost across four eval drives), **violates ±4 s lookahead** (67 outputs at ±5 s), and **distorts event comparison** via different `usableQualities`.

C5.1 is a **gated repair layer**: C4 remains default; repair runs only inside **evidence-defined suspicion windows** and only when a repair candidate **beats** the incumbent C4 sample on explicit acceptance rules.

## Layered pipeline (offline-first, same inputs as C4)

```
Position grid (1 Hz AVG buckets, unchanged acquisition)
        │
        ▼
┌───────────────────────────────────────┐
│  C4 — computeC4AdaptiveL3 (frozen)     │  ← authoritative baseline per label
└───────────────────────────────────────┘
        │  per-label: valueKmh, quality, flags, supportLabels, estimator
        ▼
┌───────────────────────────────────────┐
│  Eligibility — suspicion windows W_k   │  deterministic, flag + geometry rules
└───────────────────────────────────────┘
        │  labels ∉ ⋃W_k → PASS_THROUGH (no C5.1 code path)
        ▼
┌───────────────────────────────────────┐
│  Repair engine — PTQ subset (C5.1)     │  only inside W_k; max lookahead ±4 s
└───────────────────────────────────────┘
        │  REPAIR_ACCEPTED | REPAIR_REJECTED | UNCERTAIN
        ▼
┌───────────────────────────────────────┐
│  Output contract — C5_1_SPEED_SAMPLE   │  merges into series for eval/events
└───────────────────────────────────────┘
```

**Non-goals:** No replacement of C4 module, no DIMO/OBD authority, no new workers, no change to hard teleport quarantine upstream of C4.

## Pass-through guarantee (by design)

For label `t`:

1. If `t` is **not** in any **active** repair window `W` (see `ELIGIBILITY_AND_REPAIR_SPEC.md`), output is **bit-identical** to C4: same `valueKmh`, `quality`, `supportLabels`, `supportSpanS`, `flags`, `estimator` tag remains C4 version; C5.1 adds only `repairState: PASS_THROUGH` in research metadata (not in production `MotionCoreSpeedSample` until a future contract extension).

2. If `t ∈ W` but repair is **rejected** or **uncertain**, output reverts to **C4 unchanged** (not null, not masked unless C4 already null).

3. If `t ∈ W` and repair **accepted**, only `valueKmh` and **derived** quality/flags for that label may change; hard-quarantine labels (`OUTLIER_REJECTED`) are **never** repaired.

This directly addresses C5 V0’s 115 lost seconds: loss came from global re-estimation with insufficient support, not from C4 failure.

## Time semantics

- **Estimate anchor:** unchanged — bucket label start UTC (same as C4 / frozen L3).
- **C5.1 repair lookahead:** calendar seconds **inclusive** `[t−4, t+4]` on the motion-core grid; **no** post-loop use of `half=5` (explicit spec fix vs V0 bug).
- **Finalization:** C5.1 may depend on labels up to `t+4` for repair at `t`; labels outside repair windows do not trigger repair at `t`.
- **Unknown true measurement time:** repair outputs carry `TIME_UNCERTAINTY_DECLARED`; never emit “reconstructed true time” fields.
