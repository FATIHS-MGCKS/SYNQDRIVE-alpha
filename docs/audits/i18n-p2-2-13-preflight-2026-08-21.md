## 19. Did P2.2.11 make Operator Handover cheaper?

**Yes — materially.**

| Factor | Quantified benefit |
|--------|-------------------|
| Reusable `handover.protocol.*` keys | **~30–35** direct |
| Reusable test/guard patterns | P211 blind-spot grep + localization test template |
| Reusable adapter pattern | `handover-i18n.ts` → `operator-handover-i18n.ts` |
| Operator-specific new keys | **~45–55** (vs ~70–80 for invoice list) |
| Semantic differences | Operator wizard steps, payload validation, technical observations chips — need **B/C** keys not pure reuse |
| Machine-contract differences | Same `PICKUP`/`RETURN`, same damage enums, same `reportedBy: 'Handover'` freeze |

**vs Invoice List:** similar total debt (~85–90) but **lower reuse (12–14)**, **higher new-key count (~75)**, **medium Category E** on payment/status filters, and **no architectural completion** of deferred P2.2.11 work.

**Operator Handover wins** on reuse efficiency, bounded scope, Category E clarity, and completing intentional P2.2.11 exclusion — not on raw scanner count alone.
